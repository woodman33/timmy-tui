# Demo runbook — "Buy the run, not the file" (shoot 2026-08-22)

> One-night demo: Timmy generates an image → laser it onto a coaster →
> show prompt / reasoning / workflow / result / receipts → sell the package
> for $3 → a *different* agent (different LLM + harness) reproduces it, then
> tweaks params for a unique variant. Launch cut on X + Product Hunt.

## Framing (say this, in this order)

1. **Hook — physical first.** Hold the coaster: "An agent designed this.
   The workflow that made it costs $3, and any agent can run it."
2. **Provenance is the product.** The package isn't a JSON file — it ships
   with a signed receipt chain: prompt hash, params, logs, result hash.
   You're buying a verified, reproducible run.
3. **Sliders.** Houdini analogy: the workflow exposes named, typed params.
   Same package, different values → your own flavor. (This is literally the
   fragment/blueprint params model already in the repo.)
4. **Two reproductions, two messages.**
   - Run A (defaults, different LLM + harness): *similar* result →
     "the package is portable knowledge, not a lucky seed."
   - Run B (params tweaked): *unique* result → "you bought a tool,
     not a picture."
5. **Roadmap tease (one line, at the end).** "v2: agents buy *execution* of
   each other's workflows without the workflow ever being disclosed —
   escrowed, judged, receipted." Do not demo v2. Do not explain v2.

## Hard rules for tonight

- **Zero new venue code.** The $3 purchase is a Stripe payment link /
  Gumroad / manually-sent file. Theater is allowed; new payment code is not
  (ADVICE.md §4: fake-money before Stripe code — a payment *link* is fine,
  a payment *integration* is not).
- **Pre-run everything, record real runs, edit tight.** Nothing generates
  live on camera. Laser runs as a timelapse.
- **The second agent must be genuinely foreign.** Different model AND
  different harness (e.g. Timmy/Qwen sells, Cursor/Claude or Codex buys and
  runs). Same-harness reproduction proves nothing on camera.
- **Receipts on screen or it didn't happen.** Every segment ends on the
  receipt/log view, even for two seconds. That's the brand.

## The package manifest (define it tonight — this is the lasting artifact)

The demo forces the listing schema into existence. Draft, to be refined:

```json
{
  "schema_version": "timmy-package/0.1",
  "package_id": "<uuid>",
  "title": "…",
  "price_usd": 3,
  "seller_pubkey": "<SPKI PEM — from .timmy/keys>",
  "workflow": { "blueprint": "…", "fragments": ["…"] },
  "params_schema": [
    { "name": "…", "type": "STRING|INT|FLOAT|COMBO", "default": "…", "description": "…" }
  ],
  "provenance": {
    "prompt_hash": "sha256_…",
    "result_sha256": "…",
    "receipt_head": "sha256_…",
    "receipts": ["<excerpt of the signed chain for the original run>"]
  },
  "reproduction": {
    "harness_notes": "what a foreign agent needs (models, keys, tools)",
    "judge": "deterministic success check the buyer can run (hash/dims/schema)"
  }
}
```

Notes:
- `provenance.receipts` reuses the existing chain format (`src/utils/receipts.ts`)
  — no new receipt code, just an export path.
- `params_schema` reuses the fragment param vocabulary — no new type system.
- `reproduction.judge` plants the deterministic-judge seed (ADVICE.md §2)
  in the very first listing.

## Timeline risk (be honest with yourself)

Generation + laser + paint + two foreign-agent runs + edit is a full evening
IF everything works first try. Pre-shoot order: (1) generate + pick the image
early, (2) start laser/paint immediately — it's the long pole and dries while
you do screen captures, (3) foreign-agent runs, (4) edit. If the foreign-agent
run fights you past ~30 min, ship the X cut with Run A only and post Run B
as the follow-up tweet tomorrow — a 2-post arc is better than a 3am launch.
