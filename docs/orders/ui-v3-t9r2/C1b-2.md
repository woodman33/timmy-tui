# ORDER ui-v3-t9r2 · C1b-2 — evidence states on every carrier · HOLD

## The rule applied

The law's `evidence` block names five states and says every element that carries evidence carries exactly one. C1b-2 gives the TUI that model and wires it into every carrier in the v2 shell. The state chooses the look; no carrier chooses a colour for itself:

| state | meaning (the law) | mark |
|---|---|---|
| declared | asserted, not yet built | `○` white outline |
| constructed | built, not yet checked | `●` white fill |
| checked | verified against a receipt or a measurement | `✓` SEAL green, bold |
| inferred | a model produced it, measured:false | `◉` GENERATED violet |
| stale | was checked; its inputs changed since | `◌` PREDICT amber, dim |

Refusal is not an evidence state: it is the REFUSE accent and renders `×` red, so a refused row can never masquerade as evidence. A row that carries no evidence at all marks itself `·`.

**Two levels.** A *receipt* is constructed once sealed and checked only when a receipted chain verify covers it (its index is at or before the head the verify names); whatever follows the verify is constructed again, and the verify itself goes stale. A *claim backed by a receipt* — a journey step done, a run sealed — is checked by that receipt: the law's "verified against a receipt". Precedence when facts collide: refused > stale > inferred > checked > constructed > declared. The review asked for a single reading; this is the one taken, and it is the operator's to overturn at HOLD.

**Glyph reservation.** The circle set `○ ● ✓ ◉ ◌` belongs to evidence. The card diamonds `◇/◆` stay chrome (the Active Pane Invariant, unchanged), connectivity moved from `●/○` to `■/□` (header, footer, STATUS, FLEET, COMMANDER, the v1 layout), attention stays `▶`, progress `▮▯`. A contract test proves the two sets disjoint.
