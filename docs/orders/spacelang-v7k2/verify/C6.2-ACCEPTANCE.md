## Required behavior

Use `/status` to identify an existing service. The current capability handshake is `{service, apiVersion, capabilities, instanceId, projectHash, sourceDigest}`; all fields must be schema-validated, and the project/source/instance must match the intended selection before reuse. A legacy service without `capabilities` retains its validated legacy Open path, while Workspace reports **upgrade needed**. Missing legacy capability metadata does not establish current capabilities. A malformed or foreign current handshake must not be silently downgraded to legacy.

Maintain a per-project discovery record with `{pid, port, instanceId, version}`. Treat it as a discovery hint: live identity, process lifetime and selected project/source decide reuse. Stale records cannot authorize opening another process or project. Never spawn on an occupied port. Limit one resolution to at most five total probes, including retries/fallbacks, with backoff and a frozen overall deadline. No unbounded nested retry loop is allowed.

One `resolveVisionEndpoint()` supplies CLI, TUI and companion. Each displays `project · host:port · version · existing | started` using the selected endpoint and truthful observation. Unknown legacy version stays unknown; no invented version/identity. Clearly distinguish **Open existing** from **Start and open**. A source grep gate rejects executable raw `4336` references outside the resolver; the scan scope and resolver path are frozen before execution. Documentation and intentionally named test fixtures are not executable defaults.
