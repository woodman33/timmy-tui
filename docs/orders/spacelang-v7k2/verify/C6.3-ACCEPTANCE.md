## Finding and required outcomes

**P2-1:** immediate Save → reload and Save → Restore → reload displayed an empty board in fresh private browser contexts, although the explicit checkpoint remained recoverable. A separate 1.5-second delayed-reload diagnostic retained the note. This is a persistence/recovery gap, not established permanent loss. An exit-0 diagnostic did not qualify those failed behaviors.

Save must capture one coherent document revision and resolve only after its IndexedDB transaction **commits**, recording and returning `{rev, sha256}` for exactly that retained snapshot. A request's `success` event, a localStorage write, an in-memory store change, a timer or a queued write is insufficient. Both the browser API and Save button must await the same durable boundary before reporting success. A later edit while Save is pending must not silently change which revision the acknowledgment names.

The checkpoint payload and its revision/hash pointer must be mutually consistent after commit or interruption. On boot, wait for the actual persistence-load boundary, hash the loaded document using the frozen canonicalization, then compare it to the pointer: an empty or older board offers **Recover checkpoint rev N** with the actual retained revision; an equal revision and hash needs no recovery; a newer autosaved revision is kept. An empty document with a valid newer revision can be an intentional deletion and must not be replaced by an older checkpoint. A same-revision hash mismatch, incomparable lineage or corrupt pointer is an integrity/unknown state, never permission to overwrite.

Recovery is explicit and rechecks current revision immediately before applying: boot-time observations cannot authorize replacement of edits made afterward. Save → Restore uses the existing explicit replacement confirmation. Recovery/Restore success must also wait for durable commit so its acknowledged result survives immediate reload. Fail on a silent empty board without the required recovery offer, inaccessible acknowledged checkpoint, premature success, wrong revision/hash, lost newer edit, stale overwrite, or concealed integrity failure.

Behind a flag that is off by default, add local Vision-server snapshots through **TLSocketRoom from `@tldraw/sync-core` exactly 3.15.0** and **`node:sqlite`**. Keep the pinned tldraw 3.15.0 browser path and watermark. Store canvas asset bytes by SHA-256, verify bytes on retrieval, and expose accurate asset counts in exports. A JSON reference is not an included asset or a complete portable media backup. The flag adds no edge deployment or implicit migration of existing boards.
